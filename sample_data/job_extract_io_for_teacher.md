# 岗位提取输入/输出说明（给老师对照）

日期：2026-09-14

## 1. 以前有没有完整 I/O 日志？

**没有。** 旧流水线只写两类摘要，不保存每次模型的原文输入和 JSON 输出：

| 文件 | 内容 |
|------|------|
| `logs/pipeline.log` | 启停时间、文章目录、去重行数 |
| `logs/non_recruitment.log` | 标题过滤掉的非招聘文、空岗位列表 |

因此草稿箱里最近大量「招聘岗位汇总」，**无法从历史日志逐条回放模型当时返回了什么**。下面第 2 节是根据后台草稿箱现象 + 旧提示词行为做的问题复盘，便于对照；第 3 节是本周补上的日志格式。

## 2. 草稿箱问题复盘（招聘岗位汇总）

后台草稿可见规律：

- **岗位名称**几乎全是「招聘岗位汇总」（公众号汇编标题）
- **公司**写成「珠海格力电器2027届秋季校园招聘」这类**活动标题**，而不是单位名
- 城市常为空，投递截止常被写成同一天
- 来源为自动导入

对应到旧抽取逻辑，典型失败形态是：汇编文按「每个栏目/每家企业」只吐出 1 条，并且把**文章标题**填进岗位名称。

**旧输出（问题形态，示意）：**

```json
{
  "岗位名称": "招聘岗位汇总",
  "单位名称": "珠海格力电器2027届秋季校园招聘",
  "投递截止日期": "2026-10-13"
}
```

**期望输出（修复后，同一段原文应拆条）：**

```json
{
```

## 3. 现已落盘的日志（请老师看这个）

配置 `llm_io_log` 后，每一次抽取（爬虫汇编 + 管理员粘贴）追加一行：

- `logs/job_extract_io.jsonl` — 全量
- `logs/job_extract_io_latest.json` — 最近一次，方便转发

每条字段：

| 字段 | 含义 |
|------|------|
| `ts` | 时间（上海时区） |
| `channel` | `crawl` 爬虫抽取 / `admin` 管理员智能解析 |
| `model` | 实际调用的模型（管理员默认走 chat，不走 reasoner） |
| `article_title` | 文章标题或粘贴文本首行 |
| `source` | Markdown 路径或 `admin` |
| `duration_ms` | 耗时 |
| `input` | 发给模型的 system + user |
| `output` | 模型原文 |
| `parsed_count` | 解析后的岗位条数（jsonl 里可能为 0，以 output 为准） |

本地若尚未跑过 LLM，该文件不会出现；跑通一次后即可把 `job_extract_io_latest.json` 发给老师。

字段示意见 `job_extract_io_examples.jsonl`（结构示例，不是线上历史 dump）。

## 4. 管理员端「智能解析」相对爬虫文的差异

辅导员粘贴文本与公众号爬取文不同，已单独做一版（仍共用字段枚举）：

1. 可能出现 **学院内推、大实习、小实习**；内推写入「其他要求与投递说明」，大小实习写入招聘类型。
2. 日期经常 **没有年份**，按调用当天补全（截止日若今年已过则用明年）。
3. **尽量缩短等待**：`deepseek-chat` + `response_format=json_object`，提示词要求直接出 JSON、不走思考链。

接口：`POST /internal/job/parse`，样例文本在 `sample_data/admin_jobs/`。
