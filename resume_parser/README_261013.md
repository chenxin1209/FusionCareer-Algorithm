# 简历解析算法 261013 版说明

## 本版解决的问题

261013 版针对试用反馈做了并行升级，旧版文件和旧启动入口均未改动：

- 模型输出中的教育、实习、校园和作品经历改为数组，每段经历必须是独立元素。
- 最终仍返回旧接口所需的字符串字段。实习以及校园/项目经历统一显示为首行“单位/项目 | 岗位/角色 | 时间”、次行“具体任务与成果”，不同经历之间使用两个换行符分隔，避免内容堆叠。
- 分类不再把“出现企业名”当成实习证据。高校互培、企业命题、竞赛和营销策划项目在没有实习/任职证据时保留为校园或非雇佣项目经历。
- 对模型偶尔返回的单段多经历增加日期边界拆分，并按时间倒序排列。
- 增加校园/实习冲突提示、保守重分类和相似经历去重。
- `basic_info` 只保留 GPA、排名等没有独立字段承载的内容；联系方式、院校、专业等不再重复。
- 语言成绩和技能统一归入 `skills`，从个人简况和备注中删除重复项；复合备注会先拆分，避免删除英语内容时误删其他信息。
- PDF 正文与表格做重复行过滤，避免同一内容被 `pdfplumber` 提取两次；对有清晰中央栏沟的文本型 PDF，按左栏完整内容、右栏完整内容的顺序提取，并以字符覆盖率和跨栏表格检查自动回退。
- OCR 清洗会保护栏目标题和日期开头，避免相邻栏目或相邻经历被直接拼成一行。

## 261013 版文件

- `prompt_261013.py`：结构化抽取提示词和唯一归类规则。
- `parser_261013.py`：分段、分类、去重、排序和兼容输出。
- `extractors/pdf_extractor_261013.py`：PDF 提取与表格重复过滤。
- `llm/deepseek_client_261013.py`：DeepSeek JSON 调用及无效 JSON 的一次重试。
- `llm/io_log_261013.py`：模型输入、原始输出、解析输出和归一化结果日志。
- `config_261013.py`、`routers/internal_261013.py`、`main_261013.py`：版本化服务入口。
- `../resume_parser_example_261013.py`：不会覆盖旧导出文件的命令行示例。
- `../tests_261013/test_resume_parser_261013.py`：不调用真实模型的匿名回归测试。

## 启动方式

旧的 `resume_parser/main.py` 仍指向旧解析器。要试运行新版本，必须显式使用 261013 入口：

```powershell
python -m uvicorn resume_parser.main_261013:app --host 0.0.0.0 --port 8000
```

健康检查返回的 `resume_parser_version` 应为 `261013`，并用 `deepseek_configured`、`log_actor_hash_configured` 提示部署配置是否齐全。解析接口路径保持为：

```text
POST /internal/resume/{user_id}
```

成功响应仍使用 `message: "success"`，追踪编号放在响应头 `X-Resume-Trace-Id`，避免破坏旧前端对成功消息的判断。

DeepSeek 配置继续通过环境变量提供，不要把密钥写进代码或日志：

```text
DEEPSEEK_API_KEY
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

## 模型输入输出日志

默认按天写入：

```text
logs/resume_llm_io_261013/model_io_261013_YYYY-MM-DD.jsonl
```

同一个 `request_id` 可能对应三类事件：

- `model_attempt`：每次真实模型调用的输入、原始输出、JSON 结果、耗时和 token 用量。
- `normalized`：确定性后处理后的最终字段，便于判断问题来自模型还是算法后处理。
- `pipeline_error`：文件提取、输入校验或归一化阶段的错误；不会把原始异常内容返回给用户。

建议部署配置：

```text
RESUME_MODEL_IO_LOG_ENABLED=true
RESUME_MODEL_IO_LOG_DIR=logs/resume_llm_io_261013
RESUME_MODEL_IO_LOG_INCLUDE_SENSITIVE=false
RESUME_MODEL_IO_LOG_MAX_TEXT_CHARS=120000
RESUME_MODEL_IO_ACTOR_HMAC_SECRET=<由部署环境安全注入的随机密钥>
```

默认日志会遮盖已识别的姓名、手机号、邮箱、微信、地址、学号和证件号，并使用 HMAC 保存用户关联标识；API Key 不会进入日志。需要注意：简历经历、学校和项目本身仍可能构成个人信息，因此这是“去直接标识化调试日志”，不是匿名数据。生产环境应限制目录访问权限，设置 7—14 天的外部轮转/清理策略，不要启用 `RESUME_MODEL_IO_LOG_INCLUDE_SENSITIVE=true`。

## 回归测试

测试全部离线运行，不读取 API Key，也不调用 DeepSeek：

```powershell
python -X utf8 -m unittest discover -s tests_261013 -p "test_*_261013.py" -v
```

覆盖内容包括：

- 多段实习和校园经历分段；
- 实习和校园/项目经历的标题字段重排、详情换行及重复格式化幂等性；
- 校园项目与实习的保守分类；
- 企业命题/高校互培不误判为实习；
- 同一经历换一种表述后的跨字段去重；
- 英语成绩和技能重复清理；
- GPA、排名保留以及个人信息去重；
- OCR 标题与日期边界；
- 日志脱敏、追踪和写入失败降级；
- 旧字段类型及成功响应兼容性。

## 前端展示要求

算法返回的 `education`、`internship`、`campus`、`portfolio` 使用两个换行符分隔不同条目。其中 `internship` 和 `campus` 的单条结果内部还使用一个换行符分隔标题与详情，例如：

```text
新东方教育科技有限公司 | 市场营销部AIGC视频运营实习生 | 2025.09-至今
负责AI内容创作，撰写创意脚本，并根据后台数据优化视频制作。
```

前端容器需要保留换行，例如：

```css
white-space: pre-wrap;
```

也可以按 `\n\n` 拆分后逐项渲染。若前端使用默认的 `white-space: normal`，浏览器仍会把换行折叠为空格，算法侧已经分段但页面看起来仍可能挤在一起。

## 当前边界

- 本次没有同学上传的两份原始 PDF，因此回归测试使用了根据反馈构造的匿名样例，没有对原文件版式作结论。
- 图片 OCR 仍沿用现有识别模块；该模块没有把坐标传给解析器，所以复杂多栏图片无法仅靠后处理完全恢复阅读顺序。本版通过提示词明确“不信任相邻栏位”、通过内容语义分类来降低错配风险。
- 文本型 PDF 的双栏检测采取“宁可漏判、不可误拆”的保守阈值；栏沟不清晰、跨栏大表格或字符覆盖率异常时会回退原有整页提取，并把原因写入布局诊断日志。
- 纯扫描 PDF 如果提取不到文字会明确报错，避免把空文本交给模型产生臆测；现阶段可先转为 PNG/JPG 走 OCR。
- 日志文件轮转和删除应由部署环境处理；代码本身不会自动删除历史调试数据。
